# Как написать расширение для Just Do Testing

Расширение поставляет один или несколько типов объектов. Автор определяет поля, правила пересчёта, проверки и генерацию JSON или текста. Приложение отвечает за JavaFX, хранение проекта, исполнение маршрутов и отчёт. [Полный пример «Доставка»](../examples/shipping-builder)

## 1. Собрать и запустить пример

Установите JDK 21. Из корня публичного репозитория SDK выполните следующие команды (в Windows используйте `mvnw.cmd`):

```shell
./mvnw clean install
./mvnw -f examples/shipping-builder/pom.xml clean verify
```

Первая команда устанавливает SDK в локальный репозиторий Maven. Вторая собирает отдельный проект расширения. Скопируйте `examples/shipping-builder/target/shipping-builder.jar` в каталог **☰ → Модули… → Открыть каталог модулей** и перезапустите приложение. В Linux путь по умолчанию — `~/.just-do-testing/plugins/`, в Windows — `%USERPROFILE%\.just-do-testing\plugins\`. После выпуска версии готовый `shipping-builder.jar` можно скачать со [страницы релизов SDK](https://github.com/stasbykov/just-do-testing-plugin-sdk/releases).

1. Создайте объект типа «Склад» и выставьте зону «Город».
2. Создайте объект типа «Партия отправлений». В поле «Родительский объект» выберите склад. Появится способ «Курьер», в списке услуг будут «Обычная» и «Экспресс».
3. Измените зону склада на «За городом». Для партии появится способ «Перевозчик», станет доступна услуга «Грузовая». Выбранная «Обычная» сохранится, «Экспресс» заменится на «Обычная».
4. Добавьте две позиции по 2 и 3 места. В предпросмотре проверьте `totalPieces = 5`. Выберите «Без родителя». Поле способа станет пустым, список услуг вернётся к обычной доставке.
5. Сохраните, откройте или экспортируйте объект. Выбор родителя и значения формы сохраняются. Родитель попадёт в пакет автоматически. Для запуска самой партии можно задать только её маршрут.

## 2. Подключить API в своём Maven-проекте

Подключите публичный API со scope `provided`. Maven возьмёт выпущенную версию из Maven Central. До публикации установите SDK локально первой командой из предыдущего раздела.

```xml
<dependency>
  <groupId>io.github.stasbykov.justdotesting</groupId>
  <artifactId>scenario-plugin-api</artifactId>
  <version>1.0.0</version>
  <scope>provided</scope>
</dependency>
```

Используйте `maven.compiler.release=21`. Классы контракта и Jackson доступны в приложении. Собственные дополнительные зависимости включите в JAR, например с помощью Maven Shade Plugin. Для библиотек с пересекающимися пакетами используйте relocation. Каждый JAR получает отдельный загрузчик с общим родительским загрузчиком API.

## 3. Зарегистрировать тип

Реализуйте `io.github.stasbykov.justdotesting.plugin.ObjectBuilder`. Его метод `type()` возвращает стабильный ID, русское название, целую версию настроек, формат результата (`JSON` или `TEXT`) и признак поддержки родителя. Затем реализуйте `BuilderPlugin`, метод `builders()` которого возвращает все типы JAR.

Добавьте в `src/main/resources/META-INF/services/io.github.stasbykov.justdotesting.plugin.BuilderPlugin` одну строку с полным именем публичного класса поставщика с конструктором без параметров, как в примере:

```text
example.shipping.ShippingPlugin
```

В основной раздел манифеста JAR добавьте:

```text
Jdt-Plugin-Id: example.shipping
Jdt-Plugin-Name: Доставка
Jdt-Plugin-Version: 1.0.0
Jdt-Plugin-Api: 1
```

Конфигурация `maven-jar-plugin`, включающая манифест в сборку, есть в [POM примера](../examples/shipping-builder/pom.xml). ID модуля и типа сохраняются в проектах, поэтому используйте их и в следующих выпусках. Номер сборки JAR можно менять независимо от версии настроек.

## 4. Описать форму и её зависимости

`defaults()` создаёт исходное дерево настроек нового объекта. Метод `form(draft, parent, event, changedPath)` принимает отдельную копию дерева, необязательный снимок родителя и причину пересчёта. Верните `Form` с согласованными значениями, полями в порядке отображения и списком ошибок.

| Событие | Когда вызывается | Что делать модулю |
|---|---|---|
| `OPEN` | Создание, открытие сохранённого объекта, подготовка сценария | Применить правила к сохранённым значениям и текущему снимку родителя. Повторный вызов с тем же состоянием должен дать тот же результат. |
| `EDIT` | Ввод, выбор, флажок, добавление или удаление строки | В `draft` уже внесена правка. `changedPath` указывает JSON Pointer, например `/items/0/pieces`. Пересчитать зависимые поля. |
| `PARENT` | Выбор другого родителя, снятие выбора или изменение родительского объекта в редакторе | Применить доступные варианты, предзаполнить зависимые поля и сохранить допустимый ручной выбор. |

`Field.input` создаёт поле строки, числа или флажка. `Field.choice` принимает список пар «стабильное значение — подпись». `Field.group` объединяет поля текущего уровня, `Field.rows` задаёт массив строк, поля строки и начальное значение нового элемента. Для поля только для чтения установите `editable=false`. Чтобы скрыть поле, исключите его из списка при следующем пересчёте. Решение о сохранении скрытого значения в черновике и его включении в результат принимает модуль.

Приложение проверяет обязательность и тип отображаемых полей, а также принадлежность значения списку. Для предметной проверки добавьте `Issue("/items/0/pieces", "Количество мест должно быть больше нуля")`. Промежуточный числовой ввод (например, `1.`) может быть строкой. Сохранение черновика доступно и при ошибках формы. Предпросмотр и запуск требуют валидных данных.

## 5. Использовать родителя

При `acceptsParent=true` редактор предлагает объекты проекта. Расположение в дереве и имя служат для отображения, связь хранится по UUID. Выбрать себя или своего потомка нельзя. Для родительского конструктора `Parent.values()` содержит сохранённые настройки с версией `Parent.version()`. Для ручного JSON это дерево введённых значений, для текста — строка. У ручных объектов `pluginId` пуст, `typeId` равен `json` или `text`. Форма получает `Optional.empty()`, если родитель отсутствует или его JSON пока нельзя прочитать.

Проверяйте ID типа, версию и те поля, от которых зависит правило. Подставляйте предусмотренное значение по умолчанию или оставляйте поле пустым, если тип, значение или версия не подходят. Значение, которое будет известно только после генерации, недоступно редактору. Сохраните вычисленный режим и выбранный вариант в возвращаемых настройках, чтобы генератор получил всё необходимое. Выбор родителя не добавляет его маршрут к сценарию и не запускает его генератор.

## 6. Генерация и диагностика

`generate(settings, context)` получает проверенные настройки и номер итерации, начиная с 1. Возвращайте `new Body(text)`. Один объект генерируется один раз на итерацию, в том числе при нескольких маршрутах. Предпросмотр имеет отдельный контекст. Для согласованного идентификатора используйте `context.namedVariable().apply("uuidv7:batch")` — это значение доступно в том же запуске как `{{uuidv7:batch}}`. Готовое тело передаётся буквально. Для JSON поля доступны в шагах через JSON Pointer, например `{{/items/0/pieces}}`.

Модуль выполняет локальные вычисления. Длительные циклы должны вызывать `context.checkCancelled()`. На один вызов установлено ограничение 10 секунд. При ошибке генерации транспортные действия этой итерации не начинаются. Ошибку можно увидеть в журнале, а при ошибке подключения сформированное тело доступно и во вложениях Allure.

Для дополнительного маскирования верните `new Body(text, List.of("/customer/phone"))`. Для скрытия всего тела используйте `List.of("")`. Это влияет на предпросмотр, диагностику и отчёт. Транспорт получает оригинал. Настройки формы входят в проект и экспорт, поэтому предназначены для несекретных данных. Устанавливайте доверенные JAR: модуль исполняется с правами приложения.

## 7. Обновления и диагностика установки

При изменении схемы увеличьте версию настроек и реализуйте `migrate(from, settings)`. Передаётся копия данных. Верните обновлённое дерево или выбросьте исключение с понятным сообщением при неподдерживаемой версии. Сохранённый файл проекта меняется при явном сохранении. Если модуль отсутствует, можно открыть, сохранить или экспортировать проект с исходным определением. Остальные объекты и сценарии доступны.

Если тип отсутствует после перезапуска, откройте **☰ → Модули…**. Проверьте имя файла службы, атрибуты манифеста, версию API и наличие только одного JAR с данным ID. При одинаковом ID оба файла помечаются как конфликтующие. Для обновления замените прежний JAR новой версией и перезапустите приложение.
